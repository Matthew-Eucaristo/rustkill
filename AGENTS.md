# rustkill

TUI/CLI that reclaims disk space from the Rust footprint: cargo build directories (`target`, shared target/build dirs), Cargo's registry and git caches, sccache, `cargo install` tools, and rustup toolchains, `rust-docs`/`rustc-dev` components and cross targets. Go + Bubble Tea v2 + Lip Gloss v2 (+ charmbracelet/x/ansi, golang.org/x/sys, BurntSushi/toml). macOS first, Linux second, Windows best effort. Forked from nodekill's architecture; family rules: `../AGENTS.md`.

## Layout
- `internal/scan`: discovery and evidence, read-only. `walk.go` (parallel walk; finds Cargo.toml projects and build dirs by cargo's CACHEDIR.TAG + layout, never by name; never enters them, tool homes, `.app`, cloud placeholders, privacy folders), `project.go` (Cargo.toml, workspace, edition, frameworks, rust-toolchain pin), `scan.go` (build-dir items, git evidence in one batch per repo, activity rising through nested projects, liveness, `classify`, fingerprints, measuring), `cargo.go` (registry/git caches, old pre-1.85 registry folders, shared target dirs, sccache, rustup leftovers, `.crates2.json` installs), `rustup.go` (toolchains, components from rustup's manifests, pins, versions from `multirust-channel-manifest.toml`), `lock_unix.go` (non-blocking flock probe of cargo's build locks), `kinds.go` (catalog for capabilities), `refresh.go` (re-read one item before acting).
- `internal/size`: parallel du-like sizing; hard links once; APFS private size as `shared`.
- `internal/clean`: the only code that removes anything. `Act` = refresh, level check, fingerprint check, `guard.go` (cargo tag still there, project still has Cargo.toml, rustup/cargo subcommand allowlist, caches deep in home), then trash/delete or the official command; statfs before/after.
- `internal/contract`: JSON contract (schema_version 1), `docs/contract.md`. `internal/report`: text and receipt. `internal/ui`: Bubble Tea model/view. `internal/testfix`: temp crates, cargo build dirs, repos.
- `docs/rules.md`: sources for every rule and command. `packaging/homebrew/rustkill.rb`: tap formula template; `RELEASING.md`.
- `site/`: the GitHub Pages site (static HTML/CSS/JS, no third-party requests). `site/build.sh` runs `RUSTKILL_DEMO_DIR=<tmp> bash demo/setup.sh` and turns its self-checked `scan --json` into `sample.js` (fails if any build-machine path remains), so `app.js`, a replica of `internal/ui`, shows real output in `--dry-run` mode. Keep `app.js` in step when the TUI changes visibly. `.github/workflows/pages.yml` deploys on pushes to `main` that touch the site, demo or Go code, and on releases. The build only scans; never add `apply` or `--yes` to it.

## Invariants
- A build directory counts only with cargo's tag and a build layout (`.rustc_info.json`, or a profile dir with `.cargo-lock`/`.cargo-build-lock`/`.cargo-artifact-lock`/`.fingerprint`); re-checked right before removal. Inside git it must be ignored with nothing tracked (asked with `-C <toplevel>`); any git error means protected. A held build lock or a Rust process (cargo, rustc, rust-analyzer, bacon, …) working in the project means live.
- Cargo's caches have no stable cleanup command (`cargo clean gc` is nightly-only): they go to the Trash, only when well inside home and while no cargo/rustc runs and `.package-cache` is not locked. Pre-1.85 registry folders are safe only when every installed toolchain is 1.85+.
- Toolchains, components, targets and installed tools are removed only by `rustup toolchain uninstall`, `rustup component remove`, `rustup target remove`, `cargo uninstall --root $CARGO_HOME` (fixed argv, absolute executable from PATH or `$CARGO_HOME/bin`, subcommand allowlist, run from home with `scan.QuietEnv`: `RUSTUP_AUTO_INSTALL=0`, `CARGO_NET_OFFLINE=true`). rustup's default and `RUSTUP_TOOLCHAIN` are protected; unreadable `settings.toml` protects every toolchain. Tool missing → shown, protected, with the command.
- Never execute a toolchain's binaries (it moves the atime shown as "last used"): versions come from rustup's files. Pins only add notes, so fingerprints do not depend on the roots scanned.
- Every action re-reads the item (`scan.Refresh`), reports what blocks it now, refuses on fingerprint mismatch, re-checks level (review needs explicit selection; `--yes` takes safe project items only) and `clean.Check`. Symlinks are never followed or removed through.
- Default is Trash; `--permanent` deletes folders. `--dry-run`, `--list`, `--json`, `scan` never remove anything. rustkill writes no config, cache or state and never contacts the network itself. The contract only grows within a schema version.
- TUI: fell's look (columns, ● ▲ ■ ◉ badges, `? legend`), fits 60+ columns, cursor stays on top until the user moves. Render tests check every line fits at 60/80/100/140 × 16/24/40.

## Verify
`gofmt -l .` (empty), `go vet ./...`, `GOOS=linux go vet ./...`, `GOOS=windows go vet ./...`, `go test -race ./...`, `go run honnef.co/go/tools/cmd/staticcheck@latest ./...`, `go run golang.org/x/vuln/cmd/govulncheck@latest ./...`. Removal is tested only in temp dirs with the trash swapped (`clean.moveFunc`). On real directories use `--list`, `scan --json` or `--dry-run`; for an end-to-end check with real rustup and cargo, use a throwaway `HOME`/`CARGO_HOME`/`RUSTUP_HOME`.

## Demo
`demo/setup.sh` builds a fake HOME (APFS sparse image on macOS) with cargo-tagged build dirs, a Cargo home (current and pre-1.85 registry folders, git caches, `.crates2.json`), sccache, two rustup toolchains with manifests, and stand-in rustup/cargo, self-checks that every reported path is inside it and nothing is live (a cargo build running anywhere on the machine makes caches live, so record when none runs), then `exec env -i` into a clean shell. `vhs demo/demo.tape` re-records `demo/demo.gif` locally (never in CI); afterwards `hdiutil detach /tmp/rustkill-demo/home && rm -rf /tmp/rustkill-demo`. Check frames for anything from the real machine before committing.
