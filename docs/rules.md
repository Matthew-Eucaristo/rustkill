# Sources for rustkill's rules

Every rule below was checked against the tool's documentation and, where marked *verified*, against real cargo and rustup (Cargo 1.84 and 1.99, rustup 1.28) in a throwaway `HOME`.

## Build directories

- **Recognised by cargo's tag, not by name.** Cargo writes a `CACHEDIR.TAG` (the [Cache Directory Tagging](https://bford.info/cachedir/) signature plus `# This file is a cache directory tag created by cargo.`) into every target and build directory. *Verified*: `cargo build` creates `target/CACHEDIR.TAG`, `target/.rustc_info.json` and `target/debug/.cargo-lock`; with `build.build-dir` split off, the target dir keeps the tag and `debug/.cargo-lock` / `.cargo-artifact-lock`, the build dir gets `.rustc_info.json`, `.fingerprint` and `.cargo-build-lock`. Cargo's registry (`$CARGO_HOME/registry/CACHEDIR.TAG`) has the tag but none of that layout, so rustkill also requires the layout.
- **What `target` holds and how it comes back.** [The Cargo Book: Build cache](https://doc.rust-lang.org/cargo/reference/build-cache.html); [`cargo clean`](https://doc.rust-lang.org/cargo/commands/cargo-clean.html) removes the same folder. Moving it to the Trash is the reversible form of that.
- **Where build directories can be.** [`build.target-dir`, `CARGO_TARGET_DIR`, `CARGO_BUILD_TARGET_DIR`, `build.build-dir` and its `{cargo-cache-home}` / `{workspace-path-hash}` templates](https://doc.rust-lang.org/cargo/reference/config.html#buildtarget-dir). Relative config paths resolve against the folder holding `.cargo`; `config.toml` wins over the legacy `config`.
- **Liveness.** Cargo holds an exclusive `flock` on the profile directory's `.cargo-lock` while it builds. *Verified* with a build script that sleeps: rustkill reports `building` during the build and nothing after. rustkill asks for a shared lock without waiting and releases it at once.
- **Installers.** Tauri writes installers to `target/release/bundle` ([Tauri: distribute](https://v2.tauri.app/distribute/)); cargo-bundle uses the same folder.

## Cargo home

- **Layout and clearing.** [The Cargo Book: Cargo Home](https://doc.rust-lang.org/cargo/guide/cargo-home.html): `registry/index`, `registry/cache` (the `.crate` downloads), `registry/src` (unpacked from the cache), `git/db` (bare clones), `git/checkouts` (checked out from `git/db`); "In theory, you can always remove any part of the cache and Cargo will do its best to restore sources if a crate needs them".
- **No stable command.** `cargo clean gc` exists but is nightly-only (*verified*: stable Cargo 1.99 answers "the `cargo clean gc` command is unstable"; [cargo#12633](https://github.com/rust-lang/cargo/issues/12633)). Since Rust 1.88 Cargo deletes cache files unused for 3 months (1 month for local ones) by itself, only when it runs ([`cache.auto-clean-frequency`](https://doc.rust-lang.org/cargo/reference/config.html#cache)).
- **Old registry folders.** Cargo 1.85 changed how it hashes registry folder names. *Verified*: Cargo 1.84 writes `index.crates.io-6f17d22bba15001f`, Cargo 1.99 writes `index.crates.io-1949cf8c6b5b557f`. The git-protocol folder of older Cargo is `github.com-1ecc6299db9ec823`. rustkill marks the old folders safe only when every installed toolchain is 1.85 or newer, reading each toolchain's version from its `lib/rustlib/multirust-channel-manifest.toml` (`[pkg.rustc] version`) or its folder name.
- **Liveness.** Cargo locks `$CARGO_HOME/.package-cache` while it downloads or unpacks; rustkill also waits while any `cargo` or `rustc` process runs, since a build reads `registry/src`.
- **`cargo install`.** Records live in `$CARGO_HOME/.crates2.json` (`installs` → `bins`); `cargo binstall` writes the same records. [`cargo uninstall`](https://doc.rust-lang.org/cargo/commands/cargo-uninstall.html) with `--root` acts on the install root rustkill read, whatever `install.root` or `CARGO_INSTALL_ROOT` say.
- **sccache.** [Local storage](https://github.com/mozilla/sccache/blob/main/docs/Local.md): `SCCACHE_DIR`, default `~/Library/Caches/Mozilla.sccache` on macOS, `~/.cache/sccache` on Linux, `%LOCALAPPDATA%\Mozilla\sccache\cache` on Windows; capped by `SCCACHE_CACHE_SIZE` (10 GB). sccache has no command to empty it.

## rustup

- **Toolchains.** [`rustup toolchain uninstall`](https://rust-lang.github.io/rustup/basics.html#keeping-rust-up-to-date). The default comes from `$RUSTUP_HOME/settings.toml` (`default_toolchain`, `default_host_triple`, `[overrides]`); [`RUSTUP_TOOLCHAIN`](https://rust-lang.github.io/rustup/environment-variables.html) overrides it. An unreadable settings file protects every toolchain.
- **Pins.** [`rust-toolchain.toml` / `rust-toolchain`](https://rust-lang.github.io/rustup/overrides.html#the-toolchain-file): `[toolchain] channel`, or the legacy one-line file. rustup installs a pinned toolchain again on the next build there, so a pin is shown as a note, not a block.
- **Components and targets.** rustup lists what it installed in `lib/rustlib/components` and each component's files in `lib/rustlib/manifest-<component>`; rustkill measures exactly those files. *Verified*: `rust-docs` is `dir:share/doc/rust/html` (about 900 MB for Rust 1.99). Removed with [`rustup component remove … --toolchain`](https://rust-lang.github.io/rustup/concepts/components.html) and [`rustup target remove … --toolchain`](https://rust-lang.github.io/rustup/cross-compilation.html); [`rustup set profile minimal`](https://rust-lang.github.io/rustup/concepts/profiles.html) leaves docs out of new toolchains.
- **Quiet and offline.** [`RUSTUP_AUTO_INSTALL=0`](https://rust-lang.github.io/rustup/environment-variables.html) keeps rustup from installing a missing toolchain while rustkill runs a command; `CARGO_NET_OFFLINE=true` keeps `cargo uninstall` off the network.
- **Never run a toolchain.** Running `rustc` or `cargo` moves the access time rustkill shows as "last used", so versions are read from files.
