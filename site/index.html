Reclaim what Rust leaves behind.
Safely, and the official way.

Every crate you build grows a target folder. Cargo keeps every crate it ever downloaded, rustup keeps every toolchain with its offline docs, and every cargo install stays. rustkill finds all of it, shows what each one really frees and why it is safe or not, and removes only what you pick. Build folders and caches go to the Trash; toolchains, components and installed tools go through rustup and cargo themselves.

$ brew install matthew-eucaristo/tap/rustkill

What it finds

Not just target. The whole footprint.

A build folder counts only when cargo itself marked it: cargo's CACHEDIR.TAG beside its build layout, wherever build.target-dir put it. A folder merely named target never counts. On the machine, toolchains, components and tools are removed only by rustup and cargo, which rustkill runs from your home folder. Every rule links its source in docs/rules.md.

Safety model

It refuses anything it cannot verify.

Every item gets one of four levels and the evidence behind it. The same four badges as the rest of the family, so a glance tells you what a key will touch.

● safe

Rebuildable and cargo's own, git-ignored with nothing tracked inside, project idle 7+ days, nothing running in it.

s takes these in projects, a everywhere. Empty folders are skipped.

▲ review

  • the project changed or was built this week
  • it holds installers or app bundles you built
  • a build directory several projects share
  • a linked worktree an agent may still use
  • git ignores the project folder itself
  • it costs a download, or is a tool or toolchain you installed on purpose
  • a Cargo older than 1.85 still reads it

Allowed when you pick it. Never bulk-selected.

■ protected

  • git tracks files inside, or does not ignore it
  • another repository lies inside
  • rustup's default toolchain, or every toolchain when rustup's settings cannot be read
  • its tool is missing
  • the folder is not well inside your home

Shown, never removed.

◉ live

cargo, rustc, rust-analyzer, bacon or cargo-watch is working in the project, or cargo holds its build lock right now. Caches wait while any cargo or rustc runs, toolchains while rustup runs.

Nothing is allowed until it stops.

⎔Pinned to what you saw

Right before acting, rustkill reads the item again and refuses it if anything safety-relevant changed since the scan, naming what blocks it. The folder must still carry cargo's tag and layout.

⌘The official way only

Toolchains, components, targets and installed tools go only through rustup and cargo uninstall: absolute path, fixed arguments, never a shell, run from your home folder so no project's rust-toolchain.toml applies.

∅Never downloads

Commands run with RUSTUP_AUTO_INSTALL=0 and CARGO_NET_OFFLINE=true, so a cleanup never installs a toolchain. rustkill never contacts the network itself.

⌁Never runs your toolchains

Versions come from rustup's own files, so the "last used" time stays honest. Symlinks are never followed or removed through.

⌫Trash by default

Folders go to the Trash. --permanent deletes instead and turns the header red. Official commands delete by design, so the confirmation lists them apart.

◌Read-only modes

--dry-run, --list, --json and scan never remove anything. --yes takes safe project items only.

How sizes are counted

Where the space goes, and what you really get back.

Sizes are allocated blocks, like du, with hard-linked files counted once. On macOS rustkill asks APFS for each file's private size, and a FREES column appears when much of an item is shared with something outside it. Projects are only part of it: each toolchain carries its own offline docs (rust-docs, about 900 MB for Rust 1.99) and cross targets.

  • Measured, never assumed. After acting, freed space comes from the disk's free space, before and after.
  • The Trash frees nothing until you empty it, and the receipt says so. Official commands free space right away.
  • Each total is honest about its level. The header counts what is on disk, what is allowed, and what is safe, separately.

Use and automate

A TUI when you look. A contract when you script.

In the TUI, enter shows exactly what will happen and asks first. tab groups by project, framework or idle time, o sorts, / filters and ? explains every colour and key. It fits 60 columns, and NO_COLOR turns colour off.

# interactive; scans ~/dev (else the current folder)
rustkill
# other roots
rustkill ~/code ~/side
# interactive, but nothing changes
rustkill --dry-run
# plain table, read-only
rustkill --list
# headless: trash safe targets of projects idle 30+ days
rustkill --older-than 30d --yes
# machine-readable, read-only (--ndjson streams)
rustkill scan --json
# act on ids + fingerprints; each item is re-checked
rustkill apply --plan plan.json
Exit codes
0ok, or a dry run
1error before acting
2usage error, or an invalid plan
3something was refused, nothing failed
4something failed

Every item carries its id, a fingerprint of its safety-relevant state, sizes, evidence and the exact command. Paths are home-relative. The format is described in docs/contract.md and shared with the rest of the family.

Works alone, or under decruft. decruft, the family's umbrella, reads rustkill scan --json for its Rust & Cargo row and hands removals back through apply --plan, so rustkill re-checks every item with its own rules. fell, nodekill and flutterkill speak the same contract.

Uninstalling leaves nothing behind 
brew uninstall rustkill
brew autoremove                     # removes Go if it was installed only to build rustkill
brew cleanup --prune=all            # optional: clears Homebrew's download and build cache
brew untap matthew-eucaristo/tap    # only if nothing else is installed from this tap

rustkill writes no configuration, cache, log or state anywhere. On Linux, the first move to the Trash creates the standard ~/.local/share/Trash folders if they are missing. With go install: rm "$(go env GOPATH)/bin/rustkill". Anything it moved to the Trash stays there until you empty it or put it back.

Questions

Fair questions.

Why not just cargo clean, or cargo-sweep?

For one project, run inside it, cargo clean works. rustkill covers every project under your folders at once, plus everything outside them: Cargo's registry and git caches, sccache, cargo install tools and rustup's toolchains, docs and targets. It counts a folder only when cargo itself tagged it, checks git first, refuses what it cannot verify and shows what each item really frees. cargo-sweep and cargo-cache showed what a Rust machine accumulates; kondo and npkill inspired how you pick build folders.

Will it break a project?

A safe target is cargo's own build output, git-ignored with nothing tracked inside, in a project idle for a week or more, with nothing running in it and no build lock held. It comes back with cargo build, from scratch, so the first build is slow. Anything recently built, holding installers you built, shared by several projects or in a linked worktree is marked review and never bulk-selected.

Is it safe to remove Cargo's registry?

The Cargo book says any part of its cache can be removed: Cargo restores what a build needs. Sources unpack again from the local downloads without the network, so they are safe; the downloads, the index and git clones cost a download, so they are review. There is no stable command for this (cargo clean gc is nightly-only), so rustkill moves them to the Trash, and only while no cargo or rustc runs.

What are those old index.crates.io-6f17d22bba15001f folders?

Cargo 1.85 renamed its registry folders, so newer Cargo never reads the old ones. They are safe when every installed toolchain is 1.85 or newer. While an older toolchain is installed (one a project's rust-toolchain.toml pins, say), they are review, tagged "old cargo uses it".

Will it remove the toolchain I am using?

No. rustup's default and RUSTUP_TOOLCHAIN are protected, and if rustup's settings.toml cannot be read, every toolchain is. Other toolchains are review items, with a note naming the projects that pin them.

Does it need Rust, or send anything anywhere?

No. It is a single Go binary that never runs your toolchains and never contacts the network itself. The rustup and cargo commands it runs have auto-install and network access turned off. This page loads nothing from third parties either.

Can I run it from a script or CI?

Yes. rustkill --older-than 30d --yes moves the safe target folders of projects idle 30 days or more to the Trash and never touches caches, installed tools or toolchains. For anything else, scan --json and apply --plan pass ids and fingerprints, and exit codes say what happened.

I found a bug that touches the wrong thing.

That is a security issue. Please report it privately through GitHub Security Advisories, not a public issue.
